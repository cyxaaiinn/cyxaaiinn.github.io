# 作品集站点 · 原型

假数据版本，用来先看效果、定风格。三个开关都已实现，逻辑可直接沿用到真实项目。

## 文件

```
portfolio-prototype/
├── index.html                      前端页面（含兜底数据，双击也能看）
├── refresh.py                      刷新脚本（三个开关都在这）
├── api/portfolio.json              假数据（真实项目由 refresh.py 生成）
└── .github/workflows/refresh.yml   定时刷新 + 部署
```

## 设计

视觉语言参考了指定的参考站（alejandromejias.com.au）的排版体系：

| 元素 | 做法 |
|---|---|
| 底色 | 暖白 `#f6f6f3` + 细点阵纹理（`radial-gradient` 铺满） |
| 视觉重音 | 荧光黄绿 `#e8f84a`，整块铺在「关于」区 |
| 页脚 | 黑底 + 超大字号 + 描边字反白 |
| 标签系统 | 全部方括号：`[01]` `[2024 — 2026]` `[AI 短剧]` |
| 字体分工 | 等宽体做编号/元信息，无衬线做大标题与正文 |
| 作品列表 | **表格行**（编号 / 标题 / 分类 / 时长 / 工具），不是卡片网格 —— 作品变多也不失控 |
| 悬停 | 整行反色（伪元素铺底，**内容零抖动**）+ 跟随光标的预览浮层 |
| 顶栏 | 实时时钟 + 作品计数 |

几个实现上的决定：

- **标题第二行用描边字**（`-webkit-text-stroke: 2.2px`），是参考站调性的一部分
- **悬停反色用 `::before` 伪元素铺底**，不改 padding —— 后者会让文字左右抖动
- **入场动画是渐进增强的**：CSS 里行默认可见，只有 JS 成功启动才加 `body.anim` 启用隐藏动画。脚本一旦报错，作品列表也不会永久隐身
- **光标跟随预览**只在 `(hover:hover)` 且宽度 > 680px 时启用，触屏设备自动关闭

## 三个开关

### 开关 1 · 网站总开关

控制网站整体开还是关。

| 怎么设 | 效果 |
|---|---|
| 仓库变量 `SITE_OPEN = true`（默认） | 正常输出作品数据 |
| 仓库变量 `SITE_OPEN = false` | 只输出维护标记，**作品数据一个字都不写** |

关站时 `api/portfolio.json` 里只有 `{"_site_open": false, "items": []}`，没有作品标题、没有视频链接。别人直接访问这个文件也拿不到东西——**不是前端藏起来，是根本没生成**。

关站后网站会显示一个「内容更新中」的页面。重新设为 `true` 并跑一次刷新，内容就回来。

### 开关 2 · 单条作品上架

在飞书表格里加一列**勾选框**，字段名写「上架」。

| 状态 | 效果 |
|---|---|
| 勾上 | 出现在网站上 |
| 没勾 / 空值 | **不进 JSON**，网站上完全不存在 |
| 表格没这一列 | 全部视为上架（并打印提醒） |

**排期上线的用法**：作品信息填全、附件传好，但先不勾。想让它上线的那天勾一下，下次刷新自动出现——不用重新上传、不用碰文件。

> 安全取向：表格有这一列但没填时，**视为未上架**（宁可漏，不可误上）。表格压根没这一列时，全部上架（否则整站会空掉）。

### 开关 3 · 刷新模式

控制定时任务跑不跑。**手动触发永远可用，不受这个开关影响。**

| 仓库变量 | 定时任务 | 手动点「Run workflow」 |
|---|---|---|
| `REFRESH_MODE = auto`（默认，或不设） | 跑 | 跑 |
| `REFRESH_MODE = manual` | 跳过 | 跑 |

判断逻辑就一行：

```yaml
if: github.event_name == 'workflow_dispatch' || vars.REFRESH_MODE != 'manual'
```

## 为什么开关必须做在数据层

静态站的**所有数据都是公开可下载的**。如果你只在页面上用 JS 把内容藏起来，别人打开 `https://站点/api/portfolio.json` 就看到全部。

**那不叫隐藏。** 所以：

- 单作品隐藏 → 在 `refresh.py` 里就跳过，不写进 JSON
- 网站关闭 → 连数据文件都不生成内容

## 接真实飞书数据

1. **建最小权限应用**（别复用现有那个 217 权限的）：开 `base:record:read` + `drive:drive:readonly`，发布版本
2. **把应用加为该多维表格的协作者**（给「可阅读」）—— 不做这步会读到 0 条记录且不报错
3. **表格加一列「上架」**勾选框
4. 配 4 个仓库 Secrets：

| Secret | 从哪拿 |
|---|---|
| `LARK_APP_ID` | 应用凭证页 |
| `LARK_APP_SECRET` | 应用凭证页（keychain 里取不出，要去后台复制） |
| `LARK_BASE_TOKEN` | 表格链接 `/base/` 后面那串 |
| `LARK_TABLE_ID` | 表格链接 `?table=` 后面那串（`tbl` 开头） |

5. **启用 Pages**：Settings → Pages → Source 选 **GitHub Actions**（不是 branch）
6. 手动跑一次 workflow 验证

## 本地验证

```bash
# 不连网络，只验证开关逻辑
python refresh.py --selftest

# 起本地服务预览（否则 file:// 会拦住 fetch，只能用兜底数据）
python -m http.server 8000
# 然后打开 http://localhost:8000
```

## 已知边界

- 原型用的是公开测试视频，真实项目里换成飞书附件链接
- 封面目前是 CSS 渐变（因为没有真实封面图），真实项目读 `封面` 字段
- 飞书临时链接有效期有限，所以必须有定时刷新；关掉定时任务 = 接受视频某天会播不了
